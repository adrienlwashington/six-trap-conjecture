# Security Policy

Six-Trap is a mathematical research and reproducibility repository, not a production service.

## What belongs here

Ordinary code bugs, numerical mistakes, reproducibility failures, incorrect results, and mathematical errors should be reported through the repository's normal **Issues** workflow using the appropriate template.

## Sensitive security issues

If you discover something that could expose credentials, private information, malicious payloads, or another genuine security vulnerability:

1. **Do not post sensitive details publicly.**
2. Use GitHub's private vulnerability-reporting mechanism if it is available for this repository.
3. If no private reporting option is available, open a minimal Issue requesting a private contact channel without including the sensitive details.

## Supported version

The public research release currently supported for reproducibility is **Version 1.0**, with the canonical frozen record at:

https://doi.org/10.5281/zenodo.23357210

Security reports do not replace mathematical challenge reports. A claimed counterexample, proof flaw, census discrepancy, or verifier bug belongs in the normal challenge workflow unless it also creates a genuine security risk.
